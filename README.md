# בוט WhatsApp לעמותת נוער המתנדב

בוט Node.js המבוסס על WhatsApp Business Cloud API הרשמי של Meta. הבוט מנהל שיחה מרובת שלבים לכל מספר טלפון, שומר פניות בגיליון Google Sheets, וקורא את פרטי הנציגים מגיליון נפרד.

## התקנה והרצה

1. התקינו Node.js 18 ומעלה.
2. הריצו בתיקיית הפרויקט:

```bash
npm install
```

3. העתיקו את `.env.example` ל־`.env` ומלאו את הערכים.
4. הפעילו:

```bash
npm start
```

5. הגדירו ב-Meta את ה-webhook ל־`https://YOUR_PUBLIC_HOST/webhook`.

השרת מאזין כברירת מחדל על פורט `3000`. WhatsApp Cloud API דורש כתובת HTTPS ציבורית ותקינה; `localhost` אינו מספיק גם לבדיקות ראשוניות. לפיתוח מקומי אפשר להשתמש זמנית ב־[ngrok](https://ngrok.com/), למשל `ngrok http 3000`, ולהגדיר את כתובת ה־HTTPS שהתקבלה ב-Meta. לפרודקשן מומלץ לפרוס ב־[Railway](https://railway.app/) או בשירות HTTPS קבוע אחר.

## WhatsApp Cloud API

ב־Meta Developer Dashboard הגדירו את ה-webhook עם הכתובת הציבורית, `WEBHOOK_VERIFY_TOKEN` מאותו `.env`, ואת שדה `messages`. כל בקשת POST נבדקת מול `APP_SECRET` באמצעות `X-Hub-Signature-256` לפני עיבוד. הבוט משתמש ב־Graph API `v26.0` כברירת מחדל; אפשר לשנות דרך `WHATSAPP_API_VERSION` כאשר Meta מפרסמת גרסה יציבה חדשה.

### תבנית לנציגים

הבוט שולח לנציגים את התבנית `new_lead_notification` כברירת מחדל, כדי שהעברת פנייה תעבוד גם מחוץ לחלון השירות של 24 שעות. צרו ב־WhatsApp Manager תבנית בקטגוריית **Utility** עם גוף כגון:

```text
פנייה חדשה התקבלה.
שם: {{1}}
מחוז: {{2}}
סוג בקשה: {{3}}
פרטים: {{4}}
```

המשתנים נשלחים לפי הסדר: שם, מחוז, סוג בקשה ופרטים. התבנית חייבת לקבל אישור מ-Meta לפני שתעבוד בפרודקשן; זהו תהליך חיצוני לקוד וזמן האישור משתנה. הגדירו את השם וקוד השפה ב־`WHATSAPP_TEMPLATE_NAME` וב־`WHATSAPP_TEMPLATE_LANGUAGE` אם בחרתם ערכים אחרים.

## Google Cloud ו־Service Account

1. היכנסו ל־[Google Cloud Console](https://console.cloud.google.com/), צרו Project או בחרו פרויקט קיים.
2. הפעילו את **Google Sheets API** תחת APIs & Services > Library.
3. עברו אל IAM & Admin > Service Accounts וצרו Service Account.
4. צרו מפתח JSON עבור ה־Service Account והעתיקו את תוכן הקובץ למשתנה `GOOGLE_SERVICE_ACCOUNT_JSON` כ־JSON בשורה אחת. אפשר להשתמש גם ב־`\\n` בתוך `private_key`.
5. העתיקו את כתובת `client_email` מתוך ה־JSON.
6. שתפו את גיליון **פניות** עם הכתובת הזו בהרשאת **Editor**.
7. שתפו את גיליון **נציגים** עם אותה כתובת בהרשאת **Viewer**. אם תרצו לאפשר עדכון עתידי, אפשר לתת Editor.
8. הגדירו את מזהי הגיליונות ב־`LEADS_SPREADSHEET_ID` וב־`REPS_SPREADSHEET_ID`. מזהה הגיליון הוא החלק שבכתובת שבין `/d/` ל־`/edit`.

אותו Service Account משמש לשני הקבצים, אך השיתוף של כל קובץ מתבצע בנפרד.

## מבנה גיליונות

### גיליון 1: פניות

צרו טאב בשם `פניות` (או הגדירו שם אחר ב־`LEADS_SHEET_NAME`). בשורה הראשונה צרו בדיוק את הכותרות הבאות:

| טלפון | תאריך ושעה | סוג פנייה | שם | מחוז | סוג עזרה | דחיפות | אמצעי תשלום | הקדשה |
|---|---|---|---|---|---|---|---|---|

הבוט מוסיף שורה חדשה בסוף הטבלה. אין צורך להוסיף הרשאות כתיבה לקוד מעבר להרשאת ה־Service Account.

### גיליון 2: נציגים

צרו טאב בשם `נציגים` (או הגדירו שם אחר ב־`REPS_SHEET_NAME`). בשורה הראשונה צרו בדיוק את ארבע הכותרות הבאות, כולל הסוגריים:

| מחוז | סוג (עזרה/הצטרפות) | שם נציג | טלפון |
|---|---|---|---|
| צפון | עזרה | ישראל ישראלי | 972501234567 |
| ירושלים | עזרה | ישראל ישראלי | 972501234567 |
| מרכז-שומרון | עזרה | ישראל ישראלי | 972501234567 |
| דרום | עזרה | ישראל ישראלי | 972501234567 |
| צפון | הצטרפות | ישראל ישראלי | 972501234567 |
| ירושלים | הצטרפות | ישראל ישראלי | 972501234567 |
| מרכז-שומרון | הצטרפות | ישראל ישראלי | 972501234567 |
| דרום | הצטרפות | ישראל ישראלי | 972501234567 |

יש שורה אחת לכל שילוב של מחוז וסוג. מספרים יכולים להיכתב בפורמט בינלאומי (`972...`) או עם `0` מוביל; הבוט מנרמל אותם. מספרים צריכים להיות ספרות בלבד ככל האפשר.

`getRepresentativePhone(district, type)` קוראת את הטאב ומחזירה את המספר המתאים. התוצאות נשמרות בזיכרון לחמש דקות, כך שהבוט לא פונה ל־Sheets API בכל הודעה.

## משתני סביבה

- `GOOGLE_SERVICE_ACCOUNT_JSON`: תוכן JSON של ה־Service Account.
- `LEADS_SPREADSHEET_ID`: מזהה גיליון הפניות.
- `REPS_SPREADSHEET_ID`: מזהה גיליון הנציגים.
- `LEADS_SHEET_NAME`, `REPS_SHEET_NAME`: שמות הטאבים, ברירת מחדל `פניות` ו־`נציגים`.
- `JOIN_FORM_URL`: קישור לטופס ההצטרפות.
- `WEBSITE_URL`: קישור אתר הבית.
- `PAYMENT_BANK_DETAILS`, `PAYMENT_BIT_DETAILS`: טקסטי פרטי התשלום.
- `ADMIN_PHONE`: מספר מנהל המערכת בפורמט בינלאומי ללא `+`.

## עריכת טקסטים ונציגים

כל הודעות המשתמש נמצאות ב־`messages.js`, כולל הודעות הפתיחה, השאלות, הסיכומים והודעות השגיאה. אפשר לערוך את הטקסטים שם בלי לשנות את מכונת המצבים. קישורים ופרטי תשלום נשמרים ב־`.env`.

את מספרי הנציגים עורכים בפועל בטאב `נציגים` ב־Google Sheets. השינוי נכנס לתוקף לכל היותר לאחר חמש דקות, עם פקיעת ה־cache בזיכרון או לאחר הפעלה מחדש.

## התנהגות הבוט

- הודעה ראשונה, `היי`, `תפריט` או `0` מציגות את התפריט הראשי.
- אפשר לבחור לפי מספר או מילת מפתח: עזרה, הצטרפות, תרומה, מידע.
- `תפריט` או `0` מחזירים לתפריט מכל שלב.
- קלט לא מוכר מחזיר את ההודעה "לא הבנתי, נסה שוב" ומציג מחדש את השלב הנוכחי.
- אם לא נמצא נציג מתאים, הבוט מדווח למספר `ADMIN_PHONE` ומחזיר לפונה: "קיבלנו את הפנייה, ניצור קשר בהקדם".
- נתוני הפניות נשמרים רק בזיכרון בזמן הריצה עד לסיום התרחיש, ואז נכתבים לגיליון.
